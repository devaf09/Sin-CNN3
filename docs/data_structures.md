## 2. 語板のファイル（`.pt`、torch.load(..., weights_only=False) で読む）

```
{
  "P":     Tensor (語の数, 縦, 板)   各画素の位相（ラジアン）。語板 1 枚 = P[i]
  "words": list[str]                 語（Sudachi の正規形。例: 林檎・饂飩）。P と同じ並び
  "views": list[str]                 観点の名前と並び（v2・v3: どんな・を・が・で・に・の前・の後・と・は）
  "vals":  {観点: list[str]}         観点ごとの値（よく出る順、v2・v3 は 45 個）
  "pos":   {観点: {値: 出口の場所}}   値が出口のどこに出るか（出口のずらし、実験58）
  "parents": list[str]              合成の語板だけ: 親の語（「学校の先生」なら 先生）
}
```

- v1（goban_名詞・動詞）は `views`・`pos` がなく、`vals` の並びと「(r + 9 × 観点の番号) mod 47」で出口が決まる。
- testbot01.pt は名詞・動詞をまとめた形（`P_名詞`・`P_動詞`・`NOUNS`・`VERBS`・`NPOS`・`VPOS`・`noun_count`・`verb_count`）。

### 語板の読み方（光を通す）

```python
from goban_batch import run, prob
W = run(P, n_views=9, n_vals=45 + 9)   # (語, 観点, 出口) の明るさ。出口 0〜44 = 値、45〜53 = 観点ごとの「その他」
p = prob(W)                             # 観点ごとの割合（少し平らにしたもの）
```

- 観点 v（1 から）= 周波数 v の波を入口に入れる。出口 = 周波数 10 から（`VAL0 = 10`）。
- 縦と板の数は P の形から読むので、v1〜v3 のどの器も同じ `run` で読める。
- 値の名前を知るには `pos` を逆にする: `{(観点の番号, 出口): 値}`。

## 4. 結果のファイル（公開、`results/expNN.txt`）

1 行 1 回の実行で、JSON（`{"exp": "75", …}`）。同じ実験を何度か回すと、行が足されていく。
当たり（`bits`）は、確かめ用の材料での交差エントロピー（ビット、小さいほど良い）。`table` は数えた表（平らにしたもの）の当たりで、語板の目標。

## 5. 光の器の決まり（データの形に関わるもの）

- 出口は観点ごとに **値 45（v1 は 47）+「その他」1**。器の縦を超えられない（縦 64 なら周波数 10〜63 の 54 個まで）。縦 128 なら値 100 まで置ける。
- 違う入口から同じ出口に集められる光の和は 1 まで（学び 56）。だから観点ごとに出口をずらしている（`pos`）。
- 融合は出口の明るさを足す（位相は混ぜない、学び 64）。
