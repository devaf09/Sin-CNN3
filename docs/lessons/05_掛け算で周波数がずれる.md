# 学び 05: 波と波を掛けると、周波数がずれる（差と和）

2026-10-27。実験05（experiments/exp05_mix.py）。

## 何をしたか

長さ 32 の入力の波 x と、格子の波 g を画素ごとに掛け、その FFT を見た。4 とおり:

1. 周波数 5 × 周波数 3
2. 同じで、位相をずらす（5 の波は 60°、3 の波は 20°）
3. 周波数 12 × 周波数 10（和が 22 で、32 点で表せる正の周波数の上限 16 を超える）
4. 2 本の入力（周波数 3 と 7 を足したもの）× 周波数 2

## なぜか

学び 04 で、格子の縞と入力を掛けると「差の周波数」と「和の周波数」ができ、差が 0 の区画だけが光った。
持ち主の学習器の案（入力 → 逆フーリエ変換 →（周波数格子 + 何か）× n → フーリエ変換）では、格子と掛けることが「処理」の中身になる。
差が 0 でないとき、掛け算で周波数がどこへ・どの位相で移るかを確かめておく。

## 式の予想

- cos A · cos B = [cos(A − B) + cos(A + B)] / 2。**差の周波数と和の周波数に、半分ずつ**移る。cos 1 本は FFT で N/2 なので、それぞれ N/4 = **8**。
- 位相も、差の側は φ1 − φ2、和の側は φ1 + φ2 になる。
- 別の見方（別の方法で確かめる）: **波の側で掛けることは、周波数の側では「ぐるっと回る畳み込み」**（片方のスペクトルを、もう片方のスペクトルの山の位置へずらして重ねる）。式: FFT(x·g) = (1/N)·Σ_m X[m]·G[k − m]。

## 結果

![掛け算で周波数がずれる](../images/exp05_mix.png)

| 組み合わせ | 出た山（番号: 大きさ, 位相） | 予想 |
|---|---|---|
| 5 × 3 | 2: 8, 0° / 8: 8, 0° | 差 2・和 8 に 8 ずつ |
| 5 (60°) × 3 (20°) | 2: 8, **40°** / 8: 8, **80°** | 位相は 60 − 20、60 + 20 |
| 12 × 10 | 2: 8 / **10: 8** | 和 22 は 32 − 22 = 10 に回り込む |
| (3 + 7) × 2 | 1: 8 / **5: 16** / 9: 8 | 3 → 1 と 5、7 → 5 と 9。**5 で重なる** |

ぐるっと回る畳み込みの式（素朴な和）との差は、どれも 2 × 10⁻¹⁵ 以下。

## 分かったこと

- **掛け算は、周波数を「格子の周波数ぶん」上下にずらす**（ラジオの周波数変換と同じしくみ）。大きさは半分ずつに分かれ、位相は引き算・足し算される。
- 持ち主の学習器の「逆フーリエ変換 → 格子と掛ける → フーリエ変換」は、**周波数の並びの上で、入力のスペクトルを格子のスペクトルでずらして重ねる（畳み込む）計算**になる。
- **表せる上限を超えた周波数は、反対側から回り込む**（和 22 → 10）。たまたま格子の周波数 10 と同じ番号に出た。ずれた先が、ほかの情報の場所と重なることがある。
- **2 本の入力が、ずれた先で重なる**（3 + 2 = 7 − 2 = 5）。重なった所は 16 で、元がどちらだったかは、この 1 つの番号だけからは区別できない。
  → 「混ぜる」は処理の材料にもなるし、情報が消える原因にもなる。記憶の混線（M2）の芽はここにある。
- 掛け算と足し算だけなら、何回重ねても「ずらして重ねる」の組み合わせで、結果は入力の重ね合わせのまま（線形）。
