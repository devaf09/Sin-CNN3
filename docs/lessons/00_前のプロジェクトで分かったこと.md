# 学び 00: 前のプロジェクトで何を試し、何が分かり、どこで詰まったか

2026-10-27。Sin-CNN3 を始める前に、SN2-Parts-2D（docs/memory_design.md、NOTES.md の「現時点のまとめ」、docs/ideas.md、sn2_parts_2d.py 0.11.0）と Sin-CNN2（NOTES.md 冒頭、sinwave_minimal.py 1.3.0）を読んでまとめた。数字はそれぞれの NOTES.md が正本。

## 何を試したか

- **Sin-CNN2（1 次元）**: 文字を波の速さ（角速度）にして光の場に入れ、sin の模様の板と回折を 16 回通し、レンズ（フーリエ変換）の後の明るさで答える。重みの表を持たず、板ごとに振幅・角速度・初期位相だけを学ぶ。
- **SN2-Parts-2D（2 次元）**: 同じことを 2 次元の場で。画像（MNIST 98.0%、小さな CNN 98.1%）、言語（単語 37.4%、3-gram 36.4%）まで伸びた。
- **記憶（実験87〜100）**: 4f 系（レンズ → 周波数の面の板 → レンズ）の板に、「鍵 → 値」を学習なしで重ね書きした。
  書き込みは 板 = Σ（鍵のフーリエ変換の共役）×（値のフーリエ変換）、読み出しは 鍵のフーリエ変換 × 板 → 逆変換 → いちばん明るい窓。
  ホログラムと同じ形で、計算としては「鍵と値の循環の相関を足し合わせる」ことに当たる（HRR とほぼ同じ形。ここは M2 で確かめる）。

## 何が分かったか

- 重ね書きだけで、**比率での融合**（80% + 20% で明るさが比率どおり）、**忘却**（薄い記憶から消える）、**新旧の上書き**、**確信度**（明るさで読める）、**なじみ**が起きた。
- 似た鍵で取り出せなくなる問題は、**鍵の共通部分を引く（差分記憶法）**で消えた。
- 板を増やすと容量が増える（環状 64 枚・300 種類の記憶で 90〜99.6%）。

## どこで詰まったか

1. **崩れた鍵から思い出す力**: デジタルの辞書（一番近い鍵を探す）に大きく負けた（56% 対 100%、23% 対 94%、実験100）。
2. **容量**: 1 枚の板に 200 組を超えると取り出しは 50% 前後。新しい記憶が次々来ると（約 2840 組）64 枚でも足りない。
3. **よく出る値に引っ張られる**: 値を実際の言葉にすると、まれな値の組が 5% しか取り出せない（実験90）。
4. なぜその容量なのか、なぜ崩れた鍵に弱いのかを、**式で説明できていない**。ここが Sin-CNN3 の出発点。

## 読んでいて気になった所（まだ確かめていない。M0 で小さな例を作って確かめる）

- **ぐるっと回る計算**: 回折もレンズも 4f 系も、ゼロを詰めずに FFT を使っている（コードに「周期境界（場の端から出た光は反対側から入る）」と明記されている）。光の装置では端から出た光は反対側から戻らないので、装置との食い違いになりうる。記憶の書き込み（循環の相関）では、これが「鍵をずらしても同じ」という性質の元にもなっている。
- **回折の標本化**: 画素 1・波長 1・板の間隔 64 画素・場の幅 64 画素。伝達関数の模様の細かさの目安（場の幅 × 画素² ≥ 波長 × 距離）がちょうど境目（64 = 64）に見える。折り返しが起きていないかを確かめたい。
- **記憶の鍵の作り方**: 鍵は「場の側で」位相がでたらめな模様（明るさはどこも 1）。周波数の側に移すと、大きさがそろわず（強い所・弱い所がまだらになる）、読み出しの雑音が増えている可能性がある。HRR の周波数版（FHRR）は、逆に周波数の側で大きさを 1 にそろえる。
- **正規化（norm）の混在**: 回折は norm の既定（"backward"、往復で元に戻る）、レンズと 4f 系は "ortho"。それぞれの中では往復が合っているので誤りではなさそうだが、明るさの数字を比べるときの係数に注意が要る。

どれも「間違い」と決まったわけではない。M0 で小さな再現例を作り、食い違いがあれば持ち主に報告して掲示板に【知見】として投稿する（前のプロジェクトのコードはこちらでは直さない）。

## 残った疑問
