# 学び 03: 割り切れない周波数の漏れと、窓関数

2026-10-27。実験03（experiments/exp03_leak.py）。

## 何をしたか

長さ 16 の cos を、ちょうど 2 周するもの（f = 2）と、2.5 周するもの（f = 2.5、半端）で作り、FFT の大きさを比べた。
さらに、信号の両端をなめらかに 0 に落とす「ハン窓」 w[n] = 0.5 − 0.5·cos(2πn/16) を掛けてから FFT した。

## なぜか

学び 01・02 の波は、どれも N 点でちょうど整数回まわっていた。実際に情報を載せるときは、半端な周波数を使うこともありうる（前のプロジェクトでは、角速度を学習していた）。そのとき読み出しがどう崩れるかを知っておく。

## 式の予想（素朴な和とは別の方法で）

cos を 2 本の針に分けると、X[k] は「1 周で少しずつ回る針を 16 個足す」等比数列の和になり、式 (1 − r¹⁶) / (1 − r) で書ける（r は 1 歩で回る角度の針）。
- f が整数なら、16 歩でちょうど何周かして元に戻る（r¹⁶ = 1）ので、合う番号以外は 0
- f が半端なら、16 歩で元に戻らないので、どの番号にも少しずつ残る（漏れ）

## 結果

![割り切れる周波数と半端な周波数、窓なしとハン窓](../images/exp03_leak.png)

| 信号 | 窓 | 山 | いちばん遠い番号（k = 8） | 遠くへの漏れ（山から 3 番以上離れた所のエネルギー） |
|---|---|---|---|---|
| f = 2 | なし | k = 2, 14 に 8 | 0 | 0% |
| f = 2 | ハン窓 | k = 1, 2, 3 に 2, 4, 2 | 0 | 0% |
| f = 2.5 | なし | k = 2, 3 に 4.77, 5.44 | **1.00** | **4.50%** |
| f = 2.5 | ハン窓 | k = 2, 3 に 3.41, 3.39 | 0.00 | **0.004%** |

窓なしの結果は、等比数列の和の式と一致した（差 2 × 10⁻¹⁴）。

## 分かったこと

- **半端な周波数は、1 本の線にならず、全部の番号に漏れる**。いちばん遠い k = 8 にも、山の 1/5 ほどの大きさが出る。
- 原因は「端がつながらない」こと（図の右上）。FFT は、16 点の信号がぐるっと繰り返していると見なす。2.5 周だと、最後の点から最初の点へ飛ぶ所に段差ができ、その段差がいろいろな周波数を含む。
- **ハン窓は、遠くへの漏れを 4.5% → 0.004% に減らす**。代わりに、山が太くなる（f = 2 でも隣の k = 1, 3 に広がる）・山の高さが下がる（8 → 4）。「遠くの番号を汚さない」と「近くの番号を見分ける」の引き換え。
- 情報を周波数に載せる（M1）なら、**N 点でちょうど整数回まわる周波数だけを使えば、漏れはまったく出ない**。周波数そのものを連続の数として学習・載せるなら、漏れが隣の情報を汚す。
