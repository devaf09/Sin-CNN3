# 学び 08: 鍵と値を結んで重ね書きする記憶 — なぜ覚えられ、なぜ崩れるか

2026-10-27。実験08（experiments/exp08_memory_capacity.py）。M2（記憶の容量の線）の最初の一歩。

## 何をしたか

長さ N = 256 の信号 1 本に、M 組の「鍵 → 値」を重ね書きした（M = 1〜512）。

- **書き込み**: 記憶 = Σ（鍵 ⊛ 値）。⊛ は「ぐるっと回る畳み込み」（学び 05・07）。FFT して掛けて足すだけ。光なら 4f 系の板への二重露光。
- **読み出し**: 鍵と記憶の相関（学び 07）。出てきたものに一番近い値を、候補 256 個の中から答える。

作り方を 5 とおり比べた:

| 名前 | 鍵 | 値 | 近さの測り方 |
|---|---|---|---|
| HRR | でたらめな実数（正規分布） | でたらめな実数（候補 256 個） | 内積 |
| FHRR | 周波数の側の大きさがすべて 1（位相だけでたらめ）の実数 | 同じ作り方（候補 256 個） | 内積 |
| 前型 | 前のプロジェクトの形: 場の側で位相がでたらめな複素数 | 256 か所のどれかに光の点 | 明るさ |
| 前型 + 鍵 1 | 周波数の側の大きさを 1 にそろえた複素数 | 光の点 | 明るさ |
| 前型 + ゼロ | 前型を 2 倍の長さにゼロを詰めて（回り込まない装置のつもり） | 光の点 | 明るさ |

比較相手: デジタルの辞書（鍵をそのまま全部覚え、一番近い鍵を探す: 正確な鍵なら 100%）、偶然（1/256 = 0.4%）。

## なぜか

学び 06 で、長さ N の信号には N 個の数が混ざらずに入ると分かった。ところが前のプロジェクトの記憶は、それよりずっと手前（4096 点の板に 200 組）で 50% 前後まで崩れた。「結んで重ねる」と何が起きるのかを式にして確かめる。

## 式の予想（たとえ: 合唱の中から 1 人の声を聞き分ける）

- 鍵 k で読むと、自分の組からは「k と k の相関」= 値そのもの（大きさ 1）が出る。でたらめな鍵は、ずらすと自分と打ち消し合うので、ちょうど元の値の位置にだけ山が立つ。**これが「覚えられる」理由**。
- ほかの組からは「k と別の鍵 k' の相関」が出る。でたらめな 2 本の鍵は完全には打ち消し合わず、長さ N なら大きさ 1/√N ほど重なる（分散 1/N）。これが雑音になる。
- 組が M 組あると、雑音が M 組ぶんたまり、**雑音の分散は M/N**（合唱の人数が増えるほど、1 人の声が埋もれる）。
- 候補が V 個あると、ほかの V − 1 個のどれか 1 つでも正解より大きくなれば外れる。正規分布の性質から、だいたい **1 / 雑音の大きさ > √(2·ln V)** なら当たる。V = 256 なら √(2·ln 256) ≈ 3.3。
- まとめると、**半分ほど当たる組の数 M ≈ N / (2·ln V)**。N = 256・V = 256 なら **約 23〜32 組**。N = 4096 なら約 370 組。
- 学び 06 との違い: 学び 06 では「鍵」が別々の周波数（互いにぴったり打ち消し合う）だったので、雑音が 0 だった。でたらめな鍵は、ぴったりには打ち消し合わない。

細かい式（雑音の分散の予想、pred_var）:

| 作り方 | 正しい候補の雑音 × N | ほかの候補の雑音 × N | 理由 |
|---|---|---|---|
| HRR | M + 5 | M + 1 | 自分の組の読み出しも少しぶれる（周波数の大きさがまだら） |
| FHRR | M − 1 | M | 自分の組はぴったり値に戻る |
| 前型 | M − 1 | M | 自分の組は山の位置でぴったり 1、ほかの位置に自己相関のすそ（1/N） |
| 前型 + 鍵 1 | M − 1 | M − 1 | 自己相関のすそが 0 |
| 前型 + ゼロ | (M − 1)/2 | M/2 | 雑音が 2 倍の広さに散ると見なした（下で外れる） |

## 分かったこと

- **容量の線は、式「雑音の分散 = 組の数 / 信号の長さ」でほぼ説明できる**。4 つの作り方で、正解率も雑音の分散も、式の予想と数点以内で重なった。
- **前のプロジェクトの形（前型）も、この式どおりに崩れる**。前のプロジェクトで「1 枚に 200 組を超えると 50% 前後」だったのは、4096 点・候補 256 で予想される約 370 組と同じ桁。何か計算の誤りで崩れていたのではなく、**でたらめな鍵どうしが少しずつ重なる、という結び方そのものの限界**と考えられる。
- **私の見立て「鍵の周波数の大きさがまだらなせいで雑音が増えている」は外れた**。鍵を周波数の側でそろえても（前型 + 鍵 1）、ほぼ同じ（M = 64 で 28.6 対 28.6）。式でも、違いは 1 組分（M と M − 1）しかない。
- 値を光の点にする（前型）方が、でたらめな値（HRR・FHRR）より 16〜32 組で強い。点どうしはまったく重ならない（候補どうしが直交）ため。
- **ゼロを詰める（回り込まない）と、同じ組の数で正解率が上がる**（64 組で 28.6 → 52.6%）。ただし板が 2 倍の大きさ。しかも**式の予想（73.2%）より悪い**。雑音が広い板に均等に散ると見なしたが、実際は値の点が並ぶ前半に集まる（すそが三角形の形に偏る）ためと考えられる。見立てが外れた所として残す。
- 自分の組の雑音（正しい候補）の式は、HRR で実験より大きめに出た（M = 1・4 で式 6・9 に対して実験 2.3・1.5）。組が少ないと標本も少なく、確かめきれていない。

## 「なぜ覚えられ、なぜ崩れるか」の答え（いまの理解）

1. 覚えられる理由: でたらめな鍵は、ずらすと自分と打ち消し合う。だから鍵で読むと、結んだ値の所にだけ山が立つ。
2. 崩れる理由: でたらめな鍵どうしは、完全には打ち消し合わない（長さ N で 1/√N ほど重なる）。この小さな重なりが、組の数だけ雑音としてたまる。
3. どれだけ覚えられるか: 約 N / (2·ln 候補の数)。信号を長くすれば比例して増えるが、点の数 N よりずっと少ない。
4. 点の数 N いっぱいまで覚えるには、鍵を互いにぴったり打ち消し合うもの（別々の周波数など、学び 06）にする必要がある。その代わり、鍵は決まった N 種類しか使えず、崩れた鍵への強さも別の問題になる（次の M3）。
