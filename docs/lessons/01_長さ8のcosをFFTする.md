# 学び 01: 長さ 8 の cos を 1 本、FFT する

2026-10-27。実験01（experiments/exp01_cos8.py）。

## 何をしたか

8 個の点で 1 周する cos の波 x[n] = cos(2π·n/8)（n = 0〜7）を作り、3 つの方法でフーリエ変換した。

1. **素朴な和（自作、src/naive_dft.py）**: 式 X[k] = Σ x[n]·e^(−2πi·kn/N) をそのまま書いたもの
2. **numpy.fft.fft**
3. **torch.fft.fft**

## なぜか

M0（ライブラリと計算の約束の確認）の土台になる一歩。前のプロジェクトはすべて FFT の上に作られていたので、まず「ライブラリが式どおりの値を返すか」を、答えが手計算で分かる一番簡単な信号で確かめる。自作の素朴な和は遅いが、式と 1 行ずつ対応するので、この先の確認の「ものさし」にする。

## 使った関数

| 関数 | 何をするか | 引数（既定値に頼らず明示した） |
|---|---|---|
| `numpy.fft.fft(x, n=8, norm="backward")` | 速いフーリエ変換（FFT） | `n`: 何点で変換するか（既定は x の長さ。短いと切り、長いと 0 を詰める）。`norm="backward"`: 変換では割らない（逆変換で 1/N を割る）。既定と同じ |
| `torch.fft.fft(x, n=8, dim=-1, norm="backward")` | 同じ | `dim`: どの向きに変換するか（既定は最後の向き）。ほかは numpy と同じ意味。入力を float64（64 ビット）にした |

## 式の予想（手計算）

cos は「右回りの時計の針」と「左回りの時計の針」を半分ずつ足したもの:
cos(θ) = (e^(iθ) + e^(−iθ)) / 2

フーリエ変換は「k 番目の速さで回る針を、信号の各点に掛けて全部足す」こと。信号の中に同じ速さで回る成分があると、8 点ぶん打ち消し合わずに残る。
cos の中の 2 つの針は、それぞれ大きさ 1/2 で、8 点足すと 1/2 × 8 = **4**。

- k = 1: 右回りの 1 周 → 4
- k = 7: 8 点で 7 周 = **逆向きに 1 周（負の周波数 −1）** と同じに見える → 4
- ほかの k: 足すとちょうど打ち消し合って 0

位相（針の向き）は、cos は n = 0 で山から始まるので 0。

| 0 | 0 | 0.0000 | 0.0000 | 0.0000 |
| 1 | **4** | **4.0000** | **4.0000** | **4.0000** |

| 7 | **4** | **4.0000** | **4.0000** | **4.0000** |

| 比べたもの | 差の最大値 |
|---|---|
| 素朴な和 と 式の予想 | 4.6 × 10⁻¹⁵ |
| numpy と 素朴な和 | 4.1 × 10⁻¹⁵ |
| torch と 素朴な和 | 4.1 × 10⁻¹⁵ |
| numpy と torch | 0（ぴったり同じ） |

## 分かったこと

- **3 つとも式の予想どおり**。k = 1 と k = 7 に 4（= N/2）、ほかは 0、位相は 0。
- 差の 10⁻¹⁵ は、64 ビットの数で計算するときの丸めの誤差（小数点以下 15 桁ほどで切れる）。0 のはずの所が −0.0000 や +0.0000i と符号つきで出るのも同じ理由で、意味はない。
- numpy と torch は、この例ではビット単位で同じ値を返した。
- 「後半の番号は負の周波数」: 8 点しか見ないと、7 周と逆向き 1 周は区別できない。だから実数の cos は、正と負の 2 か所に半分ずつ現れる。
- 表の大きさが N/2 = 4 になるのは norm="backward" の約束（変換では割らない）だから。norm を変えると、この 4 が別の数になる（次の一歩の候補）。

## 残った疑問・次の一歩の候補

- norm の 3 通り（"backward"・"ortho"・"forward"）で、この 4 がそれぞれ 4・√2（= 4/√8）・0.5（= 4/8）になるはず。前のプロジェクトは回折で "backward"、レンズで "ortho" を使っていた
- sin を入れると、虚部に −4 と +4（符号が逆）で出るはず
- 割り切れない周波数（例: 8 点で 1.5 周）を入れると、1 本の線にならず周りに漏れるはず
